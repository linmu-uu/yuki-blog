首页壁纸是这个站最早做的功能：进页面随机挑一张，整站配色跟着壁纸走。
但它有个说不出口的问题——图是从网上找的。找图这件事，**能用**和**敢用**是两回事，
所以这轮把四张壁纸全换成了自己出的 AI 图。

这篇不吹 AI 画得多好，只记流水线：出图 → 转码 → 裁切 → 提取配色 → 上线 → 验证。
每一步都有具体的数字和踩到的坑，想在别的站复刻这套流程可以直接抄。

## 一、为什么最后没走本地 ComfyUI

本机的 ComfyUI 是能跑的：RTX 5070 Laptop、8GB 显存，`animagine-xl-4.0` 出 1216×832 大概 16 到 18 秒一张，
配方也调顺了。但真要用在这个站上，卡在两个地方：

第一是**分辨率不够**。这个站的桌面壁纸要 2560 宽，1216 直接拉上去等于放大两倍多，糊。
补个放大模型（`4x-UltraSharp.pth`）能解决，但那又是一轮模型下载和调试。

第二是**商标**。模型是用官方宣传图训练的，prompt 里带上 `official art`，成图的角落就会出现
「Blue Archive」商标和一行版权字，负向词堆到 `(logo:1.5)` 也压不住——这就把「用 AI 绕开版权」的意义又绕回去了。

所以这轮换了条路：直接用 imagegen 出 2560 宽的成品图（三张 2560×1707，一张 2560×1440），跳掉放大这一步。
ComfyUI 那套配方留着，哪天要批量换风格再用。

## 二、出图：prompt 里最要紧的两个决定

这四张的骨架差不多，换成角色和场景就行：

```text
masterpiece, high score, great score, absurdres, very awa, newest, anime wallpaper,
blue archive, <角色名> (blue archive), 1girl, solo, cowboy shot, <发色/瞳色/光环>,
<服装>, <动作>, <场景>, looking at viewer, cinematic lighting, detailed background
```

负向词：

```text
(logo:1.5), (copyright name:1.5), (artist name:1.4), (english text:1.4),
(watermark:1.4), (signature:1.4), worst quality, low quality, bad anatomy,
extra digits, fewer digits, jpeg artifacts, blurry, nsfw
```

两条经验值得单独说：

- **保留角色名标签，删掉 `official art`。** 想要人物像本人，`shiroko (blue archive)` 这种标签是必须的；
  但 `official art` 会把画面往官方宣传图上拽，商标就是这么进来的。删掉之后，像的程度没掉，角落里的小字没了。
- **不写景别就会变成风景照。** 只写 `kivotos city street` 这种场景词，模型倾向把人物画得很小。
  加一个 `cowboy shot`（七分身）或者 `looking at viewer`，人物才会是主体。

出完还是建议裁掉 2.5% 的边缘（`crop=iw*0.975:ih*0.955`）：偶尔仍有漏网的小字，而这点像素在后面的转码里根本不重要。

四张的选角是三张角色加一张风景：砂狼白子的雨夜霓虹街道、早濑优香的教室窗边、小鸟游星野的黄昏废墟，
外加一张没有人的三一综合学园——毕竟壁纸天天看，有一张安静点的不容易腻。

## 三、转码：一张图要出三种规格

浏览器那边什么屏幕都可能，只给一种尺寸要么糊要么浪费流量，所以每张图转成三份：

| 规格 | 尺寸 | 给谁用 |
| --- | --- | --- |
| 桌面主图 | 2560 宽 | 2K 屏、视网膜屏 |
| 桌面小图 | 1600 宽 | 1080p / 1440p 屏，靠 `srcset` 自动挑 |
| 手机竖版 | 1080×1920 | 宽度 ≤768px 时换 `source` |

格式统一 AVIF，`quality: 62, effort: 4`。同尺寸拿一张图做过对照：

| 格式 | 体积 |
| --- | --- |
| AVIF q62 | 161 KB |
| WebP q80 | 188 KB |
| JPEG q80 | 300 KB |

四张原图 PNG 加起来 **15.8 MB**，转完三档分别是桌面 746 KB、小图 370 KB、手机 471 KB。
也就是说整个壁纸库的体积，比一张原图还小。

顺带说一句：壁纸清单不是写死在配置里的。`src/data/background.ts` 构建时直接扫 `public/wallpaper/desktop/`
目录，只收 `ba-*` 和 `ai-*` 两种前缀，`-1600.` 结尾的小图单独交给 `srcset`。
加图之后不用回来改代码，扔进目录、跑一遍脚本就行。

## 四、配色跟着壁纸走，是自动算的

这个站的主题色不是固定的蓝色，而是从当前壁纸里提的。每张图会被分析出三档主色、一个平均亮度：

```json
"/wallpaper/desktop/ai-desktop-04.avif": {
  "accent": "#57bffa",
  "accent2": "#927fd4",
  "accent3": "#ccaae3",
  "brightness": 0.651,
  "dark": false
}
```

这些值在构建时变成一段 CSS 变量（`--accent`、`--halo`、`--gradient-spectrum` 之类），
连卡片描边的透明度都是按主色算的。亮度那一项还有额外作用：**图越亮，英雄区的遮罩越重**，
不然亮底图上的白色标题会看不清。这次三一那张最亮（0.651），上线前专门盯了一眼标题的可读性。

## 五、两个坑

### 坑一：竖版裁切不能信自动重心

手机版是从桌面图里裁一根 9:16 的竖条出来。第一版让 sharp 自己找视觉重心
（`position: sharp.strategy.attention`），结果：

- 白子那张被霓虹灯牌带偏，裁得只剩一只手；
- 星野那张整张都是天空，人物直接被裁没了。

改成**逐张手填焦点**才稳。脚本里留了一张表，值是人物横坐标占全图的比例：

```js
const FOCAL_X = {
  "01-shiroko-neon-night": 0.46,
  "02-yuuka-window": 0.5,
  "03-hoshino-sunset": 0.77,
  "04-trinity-cathedral": 0.52,
};
```

裁的时候按高度算出竖条宽度，再用焦点反推左边的起点，最后缩到 1080×1920。
换图之后**必须自己看一眼竖版再发**，这一步没有捷径——算法猜不出「这个人才是主体」。

### 坑二：部署后查到 404，其实是缓存

部署完成后本喵顺手查了一下新图的地址，`ai-desktop-01`、`-02` 返回 404，`-03`、`-04` 却是 200，看着像文件没传全。
但在地址后面挂个随机参数再查（`?cb=123456`），四张全是 200，字节数和本地文件一模一样。
判断是部署前那次探测的 404 被边缘节点缓存住了，不是真的缺文件。

教训是：**验证带缓存的资源，随手加个随机参数**，别拿缓存结果当结论。

另外首页壁纸是 JS 随机挑的，单次访问说明不了问题。这次是真机浏览器开首页 12 次，
统计命中分布（`ai-*` 四张被抽到 3 次，比例正常），同时确认配色变量确实跟着壁纸变了。

## 六、上线结果

```bash
npm run wallpapers:ai      # 转码：2560 桌面 + 1600 小图 + 1080×1920 竖版
npm run wallpapers:palette # 提取配色，写进 wallpaper-palettes.json
npm run build              # 构建时扫目录，生成壁纸清单
npm run deploy             # 上线
```

四条命令跑完，四张 2560 宽的 AVIF 就进了轮换池，桌面和手机各自随机挑。
想换壁纸的时候，把新图丢进 `output/imagegen/`、更新一下 `FOCAL_X`、再跑一遍，
不需要动任何页面代码。

下一步大概会拿 ComfyUI 那套配方批量出几张不同季节的，换掉现在偏冷的整体色调。
不过那是另一个坑了，等踩完再写。
